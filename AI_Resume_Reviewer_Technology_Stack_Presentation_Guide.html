1 Executive Summary & System Overview

The AI Resume Reviewer is an enterprise-grade full-stack platform engineered to solve the "black box" problem of modern recruitment. Over 75% of resumes submitted online are filtered out before reaching a human recruiter due to automated Applicant Tracking Systems (ATS) parsing errors, missing technical keywords, poor typographic flow, and unquantified job bullets.

📄 Ingestion Engine

Supports multi-format binary uploads (.PDF and .DOCX) with automated buffer parsing, optical layer scanning, and structured section extraction.

🎯 Heuristic & AI Audit

Dual-layer scoring: deterministic keyword boundary matching + Google Gemini 2.0 Flash for semantic feedback and bullet rewriting.

⚡ Zero-Friction UX

Immediate guest session mode, side-by-side resume version diffing, interactive score badges, and offline fallback resilience.

4 Algorithmic Engines & AI Architecture

1. ATS Compatibility & Keyword Engine

Mechanism: Scans resume text against a proprietary technical dictionary containing 50+ keywords across 6 categories (Languages, Frontend, Backend, Databases, Cloud/DevOps, QA/Agile).

  • Regex Word Boundaries: Employs \b{keyword}\b regex matching to eliminate false positives (e.g., "Go" vs "Good").
  • Classification: Segregates matched skills from missing critical requirements with priority tiers (Critical, High, Medium).
  • Layout Compliance: Checks single-column linearity, optical extractability, and standard section title naming conventions.

2. Job Description Match Engine

Mechanism: Evaluates role fitness against user-entered job specs or dynamically pasted job descriptions.

  • Role Fit Matrix: Multi-dimensional scoring across Frontend, Backend, Cloud Infrastructure, Scalability, and Leadership.
  • Seniority Audit: Cross-references candidate years of experience and title progression against job requirements.
  • Missing Skills Roadmap: Highlights specific gaps with actionable recommendations for candidate upskilling.

3. Google Gemini 2.0 Flash Integration

Mechanism: Uses Google's next-generation LLM via the official @google/genai SDK for deep semantic critique.

  • Strict Schema Enforcement: System prompts mandate pure JSON conforming to an explicit response structure.
  • Structured Verdicts: Generates executive headlines, targeted strengths, and high-impact weaknesses.
  • Automatic Fallback: If Gemini 2.0 Flash is busy, it auto-retries on Gemini 1.5 Flash before invoking deterministic heuristics.

4. Google X-Y-Z Bullet Optimizer

Formula: "Accomplished [X] as measured by [Y], by doing [Z]"

  • Weak Bullet Point: "Handled backend APIs for the payment team."
  • Engine Optimized Bullet: "Architected resilient payment microservices, reducing API checkout latency by 34% through Redis caching and PostgreSQL query optimization."
  • Rationale: Embeds measurable KPIs, active verbs, and technical stack ownership into every bullet.

5 Composite Scoring Mathematical Formula

Overall Evaluation Score Formula

When evaluated against a target Job Description:

Overall Score = (ATS_Score × 0.35) + (JobMatch_Score × 0.35) + (Readability × 0.15) + (Impact_Score × 0.15)

When evaluated in "Resume Only" standalone mode (no target job specified):

Overall Score = (ATS_Score × 0.70) + (Readability × 0.15) + (Impact_Score × 0.15)

* Readability assesses word count density (optimal: 300–800 words). Impact score rewards quantified percentage/dollar metrics (numbers with % or $).

7 Technical Viva & Presentation Defense Guide

Prepare for evaluators' toughest technical questions with these verified, authoritative answers:

Q1 Why did you choose React 19 and Vite rather than Next.js or traditional CRA?
Answer: "We selected React 19 with Vite 6 because our application is a dynamic, authenticated Single Page Application (SPA) dashboard rather than an SEO-reliant e-commerce site. Vite leverages native ES Modules during development, providing instant Hot Module Replacement (HMR) and optimized Rollup bundling that builds in seconds. React 19 provides modern concurrent rendering and refined state synchronization without the deployment overhead of a full Next.js Node server."
Q2 How does the backend parse binary PDF and DOCX files without corrupting characters?
Answer: "We handle file ingestion using Multer, which streams files into memory buffers. For PDFs, we utilize pdf-parse to decode low-level PDF page streams into UTF-8 text while preserving linebreaks. For Word documents (.docx), we utilize Mammoth, which parses the underlying OpenXML format, extracting text and structural headings while stripping complex styling that often confuses ATS parsers."
Q3 Is the ATS score generated purely by AI, or is it algorithmic? Why?
Answer: "The ATS score is calculated using a hybrid architecture. Relying solely on LLMs for numerical scores leads to hallucination and non-deterministic variability. Therefore, our ATS scoring uses a deterministic heuristic engine with exact regex boundary scans (\b{keyword}\b) over 50+ categorized technical terms, single-column linearity checks, and word-density algorithms. Google Gemini AI is then leveraged for what LLMs do best: qualitative semantic critique and creative bullet point rewriting."
Q4 What happens if the Google Gemini API key expires or the user has no internet connection?
Answer: "The architecture incorporates Graceful Degradation. In aiAnalysisEngine.js, the Gemini call is wrapped in a 15-second timeout with error interception. If the API key is absent or fails, the platform automatically switches to a high-fidelity local heuristic engine that generates comprehensive strengths, weaknesses, and improvement recommendations without throwing errors or breaking the UI."
Q5 How does your backend prevent NoSQL Injection and Cross-Site Scripting (XSS)?
Answer: "We implemented a custom recursive sanitizer middleware (sanitize.js) that intercepts every request body, query parameter, and URL parameter. It strips MongoDB operator injection keys starting with $ or containing . (preventing queries like { $gt: '' }) and escapes HTML special entities to neutralize XSS payload injections."
Q6 How does the 'Guest Access' feature work without polluting your MongoDB database?
Answer: "Guest mode creates an atomic session record with a unique guest ID and timestamp in GuestSession.js. Guest resumes and analyses are tagged with this ID and subjected to strict server-side concurrency limits. In production, guest sessions are configured with TTL (Time-To-Live) expiration indexes, allowing automatic background cleanup by MongoDB."
Q7 What is Google's X-Y-Z formula, and how does your engine apply it?
Answer: "Google's X-Y-Z formula is: 'Accomplished [X] as measured by [Y], by doing [Z]'. Our engine inspects candidate bullet points for missing metrics. If a bullet merely lists an action without a measurable outcome, our engine restructures it to incorporate an action verb, a quantified impact percentage or latency metric, and the specific technical stack utilized."
